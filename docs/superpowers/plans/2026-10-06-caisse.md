# Caisse Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ajouter à Ohmnia une caisse : vente d'articles de l'inventaire, paiement espèces / carte / mixte, change, arrondi suisse, ticket PDF A4, journal de caisse, annulation.

**Architecture:** Logique pure dans `src/main/domaines/caisse.ts` (sans Electron, testée sur une vraie base par esbuild, comme `tests/statuts-factures.mjs`), branchée par `src/main/ipc/caisse.ts`, exposée aussi au serveur multi-postes (`registre.ts` + `droits.ts`). Le calcul d'un règlement (arrondi, change, mixte) vit dans `src/shared/caisse.ts`, pur, partagé avec l'écran. Le ticket réutilise la fabrication de PDF de `src/main/pdf.ts` via un nouvel écran d'impression `#ticket`.

**Tech Stack:** Electron, React, TypeScript, `node:sqlite`, esbuild (tests), suites `.mjs` lancées par `tests/lancer-tout.mjs`.

**Spec:** `docs/superpowers/specs/2026-10-06-caisse-design.md`

## Global Constraints

- Aucun import d'Electron dans `src/main/domaines/` ni dans `src/shared/`.
- Un nouveau canal IPC existe à **quatre** endroits : `src/main/ipc/caisse.ts`, `src/preload/index.ts`, `src/serveur/registre.ts`, `src/serveur/droits.ts` (une opération sans droit est refusée ; `npm test` le vérifie). Le nom du canal reste sur la même ligne que `ipcMain.handle(`.
- Droits : consulter = `lecture` ; vendre et annuler = `ecriture`.
- Toute colonne ajoutée à une table existante va dans `schema.sql` **et** dans `COLONNES_ATTENDUES` de `src/main/db/migrations.ts` ; une table neuve va seulement dans `schema.sql` (`CREATE TABLE IF NOT EXISTS`).
- Les textes de l'écran et du ticket passent par `t()` (clés `caisse.*`, versions `fr` **et** `en` dans `src/shared/i18n.ts`) ; `Caisse.tsx` et `ImpressionTicket.tsx` sont inscrits dans `ECRANS_TRADUITS` de `tests/traductions.mjs`. Une clé non employée fait échouer cette suite.
- Messages d'erreur du main process en français.
- Les prix de vente de l'inventaire sont **hors taxe**, comme sur les lignes de facture : assujetti ⇒ la TVA s'ajoute (`calculerMontantTva` de `src/shared/calculs.ts`) ; non assujetti ⇒ aucune TVA.
- Montants arrondis au centime. L'arrondi aux 5 centimes ne concerne **que** la part espèces, **et seulement** si `profilPays(pays).symboleDevise === 'CHF'`.
- Numéro de ticket : `T-0001`, `T-0002`… (4 chiffres minimum), jamais réutilisé, même après annulation.
- Les écritures du Journal passent par `ajouterEcritureJournal` / `supprimerEcritureJournal` (respect des exercices clôturés et de l'audit) ; l'audit par `tracerAudit`.
- Finir chaque tâche par `npm run typecheck` puis `npm test`, tous deux verts, avant le commit. Les messages de commit se terminent par `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- `CONTEXTE.md` annonce des chiffres (fichiers de `ipc/`, écrans de `pages/`, domaines) que `tests/coherence-documentation.mjs` vérifie : les mettre à jour avec les fichiers ajoutés.

## Review Focus

- Panier vide, quantité 0 ou négative, référence absente de l'inventaire → vente refusée avec un message clair, rien d'écrit.
- Part carte négative ou supérieure au total ; espèces remises inférieures à la somme à encaisser → refus, rien d'écrit.
- Taux de change 0, négatif ou vide avec une devise étrangère → refus ; devise identique à celle de l'entreprise → taux 1 imposé, pas de saisie.
- Exercice comptable clôturé à la date du jour → la vente est refusée **en entier** (ni stock débité, ni vente enregistrée, ni écriture).
- Annuler deux fois la même vente → la seconde est refusée, le stock n'est pas remis deux fois.
- Entreprise non assujettie : aucun montant de TVA sur le ticket ni en base ; assujettie : HT + TVA = TTC au centime près.
