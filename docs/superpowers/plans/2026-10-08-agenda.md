# Agenda Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ajouter à Ohmnia un agenda d'entreprise : événements, locations de matériel avec quantités et prix par jour, alerte de disponibilité, et création d'un brouillon de facture depuis une location.

**Architecture:** Calcul pur dans `src/shared/agenda.ts` (dates, chevauchements, totaux, grille du mois), logique dans `src/main/domaines/agenda.ts` (sans Electron, testée sur une vraie base par esbuild comme `tests/caisse.mjs`), branchée par `src/main/ipc/agenda.ts` et exposée au serveur multi-postes. L'écran `Agenda.tsx` affiche une grille du mois, une liste et un formulaire.

**Tech Stack:** Electron, React, TypeScript, `node:sqlite`, esbuild (tests), suites `.mjs` lancées par `tests/lancer-tout.mjs`.

**Spec:** `docs/superpowers/specs/2026-10-08-agenda-design.md`

## Global Constraints

- Aucun import d'Electron dans `src/main/domaines/` ni dans `src/shared/`.
- Un nouveau canal IPC existe à **quatre** endroits : `src/main/ipc/agenda.ts`, `src/preload/index.ts`, `src/serveur/registre.ts`, `src/serveur/droits.ts`. Le nom du canal reste sur la même ligne que `ipcMain.handle(`. Droits : `agenda:lister` et `agenda:disponibilite` = `lecture` ; tous les autres = `ecriture`.
- Tables neuves : `schema.sql` seulement (`CREATE TABLE IF NOT EXISTS`). Aucune colonne ajoutée à une table existante.
- Dates : `YYYY-MM-DD` (locations) ou `YYYY-MM-DD HH:MM` (événements). Les comparaisons de dates se font sur ces chaînes, jamais sur des `Date` locales (heure d'été).
- Une location ne modifie **jamais** `inventaire.quantite_stock`. Les lignes de la facture créée depuis une location ont `referenceInventaire: null` (sinon confirmer la facture retirerait du stock, voir `deduireStockUneFois` dans `src/main/domaines/factures.ts`).
- Les textes de l'écran passent par `t()` (clés `agenda.*` et `menu.agenda`, versions `fr` **et** `en` dans `src/shared/i18n.ts`) ; `Agenda.tsx` est inscrit dans `ECRANS_TRADUITS` de `tests/traductions.mjs`. Une clé non employée fait échouer cette suite. Les valeurs stockées (`'Réservée'`, `'Rendue'`, `'Annulée'`) se comparent aux constantes de `src/shared/agenda.ts`, jamais à un mot français écrit dans un écran.
- Messages d'erreur du main process en français.
- Montants arrondis au centime avec `Math.round(x * 100 + 1e-9) / 100`.
- `creerBrouillonFacture` et `enregistrerFacture` (`src/main/domaines/factures.ts`) ouvrent chacune leur transaction : **on ne peut pas les imbriquer** dans `dansUneTransaction`. La création d'une facture depuis une location se compense à la main (supprimer le brouillon en cas d'échec).
- Finir chaque tâche par `npm run typecheck` puis `npm test`, verts, avant le commit. Messages de commit terminés par `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- `CONTEXTE.md` annonce des chiffres (fichiers de `ipc/`, écrans de `pages/`, suites de `tests/`) vérifiés par `tests/coherence-documentation.mjs` : les mettre à jour avec les fichiers ajoutés.
- Travailler sur une branche `agenda`, fusion fast-forward dans `main` à la livraison.

## Review Focus

- Fin avant début, titre vide, location sans ligne, quantité ≤ 0, prix < 0, article ou client inconnu → refus avec message clair, rien d'écrit.
- Deux locations qui se touchent sans se chevaucher (fin le 10, début le 11) ne comptent pas l'une contre l'autre ; fin le 10 et début le 10 comptent.
- Une location annulée, et la location qu'on est en train de modifier, ne comptent pas dans la disponibilité.
- Créer la facture deux fois ; créer la facture d'une location annulée, sans total, ou inexistante → refus ; une panne après la création du brouillon ne laisse aucun brouillon orphelin.
- Supprimer un client qui a des locations → message clair, pas une erreur de clé étrangère.
- Un événement sur plusieurs jours, ou à cheval sur la fin du mois, apparaît dans chaque mois qu'il touche.

Types à ajouter dans `src/shared/types.ts` :

```ts
export type StatutLocation = 'Réservée' | 'Rendue' | 'Annulée'
export interface EvenementAgenda { id: number; titre: string; debut: string; fin: string; lieu: string; notes: string }
export interface LigneLocation { referenceInventaire: string; designation: string; quantite: number; prixParJour: number }
export interface LocationAgenda { id: number; clientId: number; clientNom: string; dateDebut: string; dateFin: string; statut: StatutLocation; notes: string; factureId: number | null; factureNumero: string | null; lignes: LigneLocation[]; jours: number; total: number }
export interface ValeursLocation { id: number; clientId: number; dateDebut: string; dateFin: string; notes: string; lignes: { referenceInventaire: string; quantite: number; prixParJour: number }[] }
export interface ContenuAgenda { evenements: EvenementAgenda[]; locations: LocationAgenda[] }
export interface DisponibiliteArticle { reference: string; stock: number; loue: number; disponible: number }
export interface ResultatLocation { location: LocationAgenda; avertissements: string[] }
```

`id: 0` désigne un élément à créer (événement ou location).
